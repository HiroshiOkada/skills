## デザインアイデア

**退屈なスライドを作らないでください。** 白い背景に単純な箇条書きでは誰も感動しません。各スライドについて、このリストからのアイデアを検討してください。

### 始める前に

- **大胆でコンテンツに基づいたカラーパレットを選ぶ**: パレットはこのトピックのためにデザインされたと感じられるべきです。あなたの色を完全に別のプレゼンテーションに入れ替えても「機能する」なら、あなたは十分に具体的な選択をしていません。
- **平等より支配**: 1つの色が支配的（60-70%の視覚的重み）であり、1-2のサポートトーンと1つの鋭いアクセントを持つべきです。すべての色に等しい重みを与えないでください。
- **暗/明のコントラスト**: タイトル+結論スライドには暗い背景、コンテンツには明るい背景（「サンドイッチ」構造）。または、プレミアム感を出すために全体を通して暗い背景にコミットします。
- **視覚的モチーフにコミットする**: 1つの特徴的な要素を選び、それを繰り返します — 丸い画像フレーム、色付きの円の中のアイコン、太い片側の境界線。すべてのスライドでそれを実行します。

### カラーパレット

トピックに合った色を選んでください — 一般的な青にデフォルト設定しないでください。インスピレーションとしてこれらのパレットを使用してください：

| テーマ | プライマリ | セカンダリ | アクセント |
|-------|---------|-----------|--------|
| **Midnight Executive** | `1E2761` (navy) | `CADCFC` (ice blue) | `FFFFFF` (white) |
| **Forest & Moss** | `2C5F2D` (forest) | `97BC62` (moss) | `F5F5F5` (cream) |
| **Coral Energy** | `F96167` (coral) | `F9E795` (gold) | `2F3C7E` (navy) |
| **Warm Terracotta** | `B85042` (terracotta) | `E7E8D1` (sand) | `A7BEAE` (sage) |
| **Ocean Gradient** | `065A82` (deep blue) | `1C7293` (teal) | `21295C` (midnight) |
| **Charcoal Minimal** | `36454F` (charcoal) | `F2F2F2` (off-white) | `212121` (black) |
| **Teal Trust** | `028090` (teal) | `00A896` (seafoam) | `02C39A` (mint) |
| **Berry & Cream** | `6D2E46` (berry) | `A26769` (dusty rose) | `ECE2D0` (cream) |
| **Sage Calm** | `84B59F` (sage) | `69A297` (eucalyptus) | `50808E` (slate) |

### 各スライドについて

**すべてのスライドには視覚的要素が必要です** — 画像、チャート、アイコン、またはシェイプ。テキストのみのスライドは忘れ去られます。

**レイアウトオプション:**
- 2列（左にテキスト、右にイラスト）
- アイコン + テキスト行（色付き円の中のアイコン、太字ヘッダー、下に説明）
- 2x2 または 2x3 グリッド（片側に画像、反対側にコンテンツブロックのグリッド）
- ハーフブリード画像（左側または右側全体）とコンテンツオーバーレイ

**データ表示:**
- 大きな統計コールアウト（下に小さなラベル付きの60-72ptの大きな数字）
- 比較列（前後、長所/短所、並列オプション）
- タイムラインまたはプロセスフロー（番号付きステップ、矢印）

**視覚的研磨:**
- セクションヘッダーの隣の小さな色付き円の中のアイコン
- 主要な統計やタグラインのためのイタリックアクセントテキスト

### タイポグラフィ

**興味深いフォントのペアリングを選択する** — Arialにデフォルト設定しないでください。個性のあるヘッダーフォントを選び、クリーンな本文フォントと組み合わせてください。

| ヘッダーフォント | 本文フォント |
|-------------|-----------|
| Georgia | Calibri |
| Arial Black | Arial |
| Calibri | Calibri Light |
| Cambria | Calibri |
| Trebuchet MS | Calibri |
| Impact | Arial |
| Palatino | Garamond |
| Consolas | Calibri |

| 要素 | サイズ |
|---------|------|
| スライドタイトル | 36-44pt 太字 |
| セクションヘッダー | 20-24pt 太字 |
| 本文テキスト | 14-16pt |
| キャプション | 10-12pt 控えめ |

### スペーシング

- 0.5インチの最小マージン
- コンテンツブロック間の0.3-0.5インチ
- 余裕を残す - すべてのインチを埋めないでください

### 避けるべきこと（一般的な間違い）

- **同じレイアウトを繰り返さない** — スライド全体で列、カード、コールアウトを変化させる
- **本文テキストを中央揃えにしない** — 段落とリストは左揃えにする；タイトルのみ中央揃え
- **サイズコントラストを節約しない** — タイトルは14-16ptの本文から目立つように36pt以上が必要
- **青にデフォルト設定しない** — 特定のトピックを反映する色を選ぶ
- **スペーシングをランダムに混ぜない** — 0.3インチまたは0.5インチのギャップを選び、一貫して使用する
- **1枚のスライドをスタイルして残りを無地にしない** — 完全にコミットするか、全体を通してシンプルに保つ
- **テキストのみのスライドを作成しない** — 画像、アイコン、チャート、または視覚的要素を追加する；単純なタイトル+箇条書きを避ける
- **テキストボックスのパディングを忘れない** — 線やシェイプをテキストの端に合わせるときは、テキストボックスに `margin: 0` を設定するか、パディングを考慮してシェイプをオフセットする
- **低コントラスト要素を使用しない** — アイコンとテキストは背景に対して強いコントラストが必要；明るい背景に明るいテキストや暗い背景に暗いテキストを避ける
- **タイトルの下にアクセントラインを決して使用しない** — これらはAI生成スライドの特徴である；代わりに空白または背景色を使用する

## QA (必須)

**問題があると仮定してください。あなたの仕事はそれらを見つけることです。**

あなたの最初のレンダリングはほとんど正しくありません。QAを確認ステップではなくバグハントとしてアプローチしてください。最初の検査で問題が見つからなかった場合、あなたは十分に見ていませんでした。

### コンテンツQA

```bash
python -m markitdown output.pptx
```

欠落しているコンテンツ、誤字、間違った順序をチェックします。

**テンプレートを使用する場合、残ったプレースホルダーテキストをチェックします:**

```bash
python -m markitdown output.pptx | grep -iE "xxxx|lorem|ipsum|this.*(page|slide).*layout"
```

grepが結果を返す場合、成功を宣言する前にそれらを修正してください。

### 視覚的QA

**⚠️ サブエージェントを使用してください** — 2-3枚のスライドであっても。あなたはコードを見つめており、そこにあるものではなく、期待するものを見るでしょう。サブエージェントは新鮮な目を持っています。

スライドを画像に変換し（[画像への変換](#converting-to-images)を参照）、このプロンプトを使用してください：

```
これらのスライドを視覚的に検査してください。問題があると仮定して、それらを見つけてください。

以下を探してください：
- 重なる要素（シェイプを通るテキスト、単語を通る線、積み重なった要素）
- エッジ/ボックス境界でのテキストオーバーフローまたは切り捨て
- 1行のテキスト用に配置された装飾的な線だがタイトルが2行にラップされている
- 上のコンテンツと衝突するソース引用またはフッター
- 要素が近すぎる（< 0.3インチのギャップ）またはカード/セクションがほぼ接触している
- 不均一なギャップ（ある場所には大きな空き領域があり、別の場所では窮屈）
- スライドエッジからの不十分なマージン（< 0.5インチ）
- 一貫して配置されていない列または同様の要素
- 低コントラストテキスト（例：クリーム色の背景に薄い灰色のテキスト）
- 低コントラストアイコン（例：対照的な円のない暗い背景上の暗いアイコン）
- 過度の折り返しを引き起こす狭すぎるテキストボックス
- 残ったプレースホルダーコンテンツ

各スライドについて、些細なものであっても問題や懸念領域をリストしてください。

これらの画像を読んで分析してください：
1. /path/to/slide-01.jpg (期待: [簡単な説明])
2. /path/to/slide-02.jpg (期待: [簡単な説明])

些細なものを含め、見つかったすべての問題を報告してください。
```

### 検証ループ

1. スライド生成 → 画像に変換 → 検査
2. **見つかった問題をリストする**（見つからなかった場合は、より批判的に再度見てください）
3. 問題を修正する
4. **影響を受けたスライドを再検証する** — 1つの修正が別の問題を引き起こすことがよくあります
5. 完全なパスで新しい問題が見つからなくなるまで繰り返す

**少なくとも1回の修正と検証のサイクルを完了するまで、成功を宣言しないでください。**

## 画像への変換

視覚的検査のためにプレゼンテーションを個々のスライド画像に変換します：

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
pdftoppm -jpeg -r 150 output.pdf slide
```

これは `slide-01.jpg`, `slide-02.jpg` などを作成します。

修正後に特定のスライドを再レンダリングするには：

```bash
pdftoppm -jpeg -r 150 -f N -l N output.pdf slide-fixed
```
